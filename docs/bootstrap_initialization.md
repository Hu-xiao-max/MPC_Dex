# Importing a simulation actor into fresh bootstrap SAC

`scripts/train_bootstrap.py --initial-actor CHECKPOINT` initializes a new bootstrap run with the checkpoint's actor trunk and mean head. This is distinct from resuming a training run. The source checkpoint and metadata must match the complete environment contract, control/observation interface, 60/16 dimensions and hidden sizes. The current successful BC diagnostic uses absolute targets, the 40 mm grasp and a 100-step horizon; incremental or 900-step configurations are incompatible with that checkpoint.

The initializer preserves imported tensors and authentic historical BC counts. Critics, target critics, all optimizers and temperature are newly initialized; the bootstrap learner configuration sets the initial standard deviation. Source critic/SAC counts are recorded as provenance and do not become new training updates or successes. A seed replay may supply explicitly requested critic pretraining. Combining an imported actor with nonzero seed BC updates is rejected to avoid silently retraining its mean.

`--steps 0` checks initialization without online interactions. A real CUDA check is recorded in `artifacts/bootstrap_import_smoke_0001/`: all 12 supervised-state actions match the source bit-for-bit for singleton and batch-one inference, and an independent nine-control audit reproduces the source's successful first turn and every physics sample exactly. The run retains BC12000, critic0, online0, zero bootstrap interactions and zero bootstrap success counts. It is not a trained SAC result or a production primitive.

Resume uses the existing output directory and cumulative `--steps` budget. The initial actor path is recovered from committed provenance if omitted. Its checkpoint and metadata hashes must still match. Resume restores the running learner, optimizer and replay states without importing the actor again, resetting standard deviation or repeating seed initialization.

Bootstrap provenance now also binds the resolved device and CUDA model/capability, Torch intra/inter-op thread counts, matmul precision/TF32, CuDNN TF32/determinism/benchmark settings, deterministic-algorithm settings and runtime versions. A mismatch rejects resume. This matters because the same weights can produce different float32 commands under CPU, singleton CUDA or batched CUDA inference. These checks do not promise universal CUDA determinism.

The initializer passed 51 focused bootstrap tests and independent review; the full suite at that implementation point passed 214 tests. The BC actor still drops under continued policy control, and all five prescribed stochastic samples fail at both latent std .05 and the existing minimum 1e−5. A fresh run, [bootstrap0005](../artifacts/bootstrap_0005/findings.md), subsequently completed 2,000 interactions and 1,745 SAC updates with fresh critics and no critic pretraining. It produced no new full-turn successes and lost the initial deterministic BC turn. Independent frozen audits found persistent critic optimism against actual terminal returns. Initialization correctness does not resolve that exploration and learning problem.

Successful prerequisite data must be collected through the [frozen policy collector](primitive_collection.md). The initializer's zero-update BC success and a changing bootstrap training history are diagnostic records, not eligible SAC primitive data.
