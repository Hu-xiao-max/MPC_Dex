# Independent implementation decisions

This workspace now implements the published learning and planning equations in Python/PyTorch/MuJoCo. It is not the authors' source and has no author-trained checkpoint. The target currently used for development is local simulation; physical hardware deployment remains unverified.

The source reference remains [paper_reference.json](../configs/paper_reference.json), which records published facts separately from the runnable [local configuration](../configs/local_sim.json). Unknown choices below are implementation decisions and are not attributed to the authors.

| Component | Implemented choice and limits |
| --- | --- |
| Robot | Pinned public Menagerie right Allegro model; see `assets/allegro/upstream.json` and retained license. No author calibration. The palm is rigidly mounted facing down, representing a stationary mounting arm. |
| Object | Free 45 mm AF hexagonal prism, 120 mm long and 150 g. Length/mass/friction are local choices. The source footage shows a separate marker-bearing extension omitted here; no axial dimension or calibrated placement is published. No object actuator, weld, imposed rotation, or supporting pivot. |
| Initial state | Fingertip IK followed by normal-gravity dynamic settling and a cold six-second hold verification. `assets/initial_grasp.npz` records the physical state and evidence; the state is initialization, not a rotation demonstration. |
| Interface | 60 observations in equation (5) order; positions and quaternion in palm frame, quaternion wxyz, finite differences over 0.1 s. No observation normalization. Joint order first/middle/ring/thumb, each joints 0–3. Normalized actions map affinely onto Menagerie actuator limits. |
| Rotation axis | Object local/palm y, measured by accumulated short-arc quaternion twist about the object's principal y axis. Positive y rotation is rewarded. Object quaternions and observed angle are measured from simulated state. |
| Dynamics | 2 ms MuJoCo integration, position gain 3, damping .1, actuator limit .7 Nm. These values require hardware calibration before any transfer. |
| RL reward | Published progress 20, elapsed−.3, full-turn+200, drop−50 overriding other terms. Training episodes end at full turn/drop or truncate at 900 control steps. Rotation palm-support failure uses the same −50 terminal penalty as an explicit local extension. |
| Drop | Object/table contact, workspace exit, or 50 ms without any finger contact. Rotation success requires a full retained turn: positive twist counts toward that turn only with at least two finger contacts and axis tilt at most 30°, while all reverse twist counts against it. These explicit local retention checks prevent thrown objects being labeled successful. |
| Networks | Tanh MLP 256×256 with LayerNorm between each Linear and tanh. Actor mean/std have separate final layers. Ten independent Q networks. |
| BC | Episode-return softmax then uniform transition within selected episode; temperature 1 is unpublished. Pre-tanh clipped-action MSE; fixed actor std.3 after BC. |
| Critic backup | Soft-SARSA uses minimum over all 10 critics; online target randomly selects 2 from 10 per the project table. This is the explicitly chosen resolution of the paper/table ambiguity. |
| SAC | Actor objective averages Q ensemble; actor LR starts near zero and warms to 3e−4 over 200k updates. Offline/online 256-sample batches contain 77/179 transitions. Eight updates per environment step in the full-method runner. |
| MPC | PCA basis plus full joint residual,350 candidates,10 elites,6 knots,.5 s horizon. Linear interpolation,3 CEM iterations, position/principal/tilt cost weights 1000/1/10 are local choices. Half samples use each published exploration/refinement floor. |
| MPC execution | Five candidate commands at 0.1 s intervals, each held for 50 simulation steps. This matches the 16D 10 Hz interface actually executed; it does not reproduce a separate 333 Hz hardware communication loop. |
| Constraint rejection | Parallel workers clone the live integration state, including warmstart and applied forces, and use the environment's `mj_step`/`mj_forward` transition. After every 2 ms they inspect actual object/finger and object/table contacts, object/palm normal force for rotation, workspace distance, finite state, and advancing simulation time. A candidate stops immediately on violation, including 50 ms without finger contact; its timer starts from the live environment's elapsed contact-loss time. The native whole-horizon helper remains available for prediction comparisons, but production scoring uses these exact workers. |
| Reorientation | Adds goal heading as observation 61 and tracks heading about palm z. The goal is ±20°, success 5° for.5 s. Same reward coefficients. This local task definition needs separate training and validation. |
| Checkpoint compatibility | Sidecars bind learner parameters, task/joint/action conventions, source/model/mesh/grasp hashes, and the fixed pretraining replay. Fresh full-method training rejects already-online-trained checkpoints rather than resetting their schedule silently. |

The companion paper obtains its rotation primitives from a successful simulation SAC policy trained on a 40 mm object. `scripts/train_bootstrap.py` is the independent path for generating successful policy trajectories, initially using the verified 45 mm scene. This difference is explicit; successful 45 mm trajectories are not represented as the authors' 40 mm dataset. Bootstrap training settings are separate from the main method's 10-critic, pretraining, mixed-replay and eight-update schedule. Optional bootstrap control uses bounded target increments with retained-rotation shaping; its replay actions are increments, and its observations contain the previously executed absolute target, with angle slots 23–24 replaced by retained angle and previous retained angle. The qualified progress controlling completion is therefore observable. Checkpoint metadata records the control interface and implementation hash so CLI evaluation restores the same controller. Primitive extraction consumes measured joint positions rather than those increment actions. MPC collection and the main learner retain absolute normalized target actions and the paper reward.

Exact rejection has measurable overhead. In one local MuJoCo 3.14.0 benchmark, 100 stable-grasp candidates each simulated for 0.1 s (50 physics steps) took 0.170 s with eight exact workers, compared with 0.028 s for native whole-horizon simulation without contact-loss rejection. Single-worker times were 0.361 s and 0.150 s, respectively. These are evaluator measurements for a smaller batch/horizon than the default CEM configuration, not demonstrated 10 Hz end-to-end planning. Adversarial contact-loss tests counted 25 executed steps per airborne candidate before rejection instead of all 250 requested steps; stable-grasp tests matched the environment's full integration state bit-for-bit and verified that evaluation left the live state unchanged.

Remaining verification includes: a successful rotation policy for primitive extraction; MPC collection of 20 successful rotations; the full BC/Soft-SARSA/online learning schedule; and policy-only evaluation. The published adaptation experiments and extended reliability claims also remain unverified. A passing implementation test or a stationary grasp does not prove any of these outcomes.

The initial bootstrap run (`artifacts/bootstrap_0001`) was invalidated after an adversarial audit found ballistic false successes: six sampled reported successes had no hand contacts and dropped within 2–30 ms. Its replay and exported traces are diagnostic artifacts only. Corrected measurement uses incremental principal-axis twist instead of an Euler projection, plus explicit grasp-retention checks. Production extraction rejects the invalidated run and older trajectory metadata. It also rejects reorientation episodes and requires per-episode angle, retained angle, contact/tilt evidence and exactly steps+1 joint-position frames. Evaluation keeps bootstrap-shaped and original paper returns separately.

The current evaluation resets are deterministic and use the same verified initial grasp; five repeated episodes do not establish robustness to varied placements. Broader reset-distribution evaluation remains necessary.

The absolute-action bootstrap experiment `bootstrap_0002` stopped after 25,856 transitions with 7,391 drops and zero full-turn successes. Its diagnosis found large command jumps and reward for fast rotation before release. `bootstrap_0003` only initialized a partial-demo policy (no online interactions), then was superseded when qualified progress became observable. These policies do not supply rotation primitives.

The physically replayed partial seed rotates 0.72106 radians (41.31°) over 8 seconds and holds for 3 seconds, with four fingertips contacting throughout all 5,500 physics steps and at most 0.92° axis tilt. Its largest target change is 0.01851 rad per 100 ms. `scripts/prepare_bootstrap_seed.py` converts its absolute commands to increments, re-executes them in the bootstrap environment, checks observations against the original, and recomputes all rewards. The final cutoff is a nonterminal truncation with no invented next action. The seed has zero full-turn successes and cannot be used for primitive extraction. This initialization is an additional independent bootstrap choice, not a reported paper setting.

`configs/bootstrap_incremental_seeded.json` uses this 110-transition seed for 5,000 BC and 5,000 frozen-actor critic updates before online bootstrap SAC. Bootstrap uses two critics, one update per online transition, initial std 0.1, and a 5,000-update actor warmup. These are separate from all main-method counts. The active experiment and process status are recorded in `WORK_STATE.md`; actual logs/checkpoint manifests remain authoritative.

Source-video geometry review is preserved in `artifacts/rotation_probe/source_audit/README.md`. The footage distinguishes a central contact body and a narrower marker-bearing extension. The extension's attachment axis and the central body's axial dimension remain ambiguous. Alignment along the wrist-to-fingertip direction is a visual inference worth testing, not an author-specified transform. The active cross-finger prism therefore remains an independent test scene.

A matched 40 mm AF grasp is available at `artifacts/grasp_40mm_0001/initial_grasp_40mm.npz` with `configs/bootstrap_40mm.json`. It passed 3,000 cold physics transitions with four force-bearing fingertips, no palm/table support and normal gravity. This matches the companion diameter only; it does not resolve other calibration/geometry assumptions. Subsequent 40 mm BC diagnostics and bootstrap0005 SAC results are recorded in `WORK_STATE.md`; none supplies a successful SAC primitive.

`scripts/audit_policy.py` snapshots a checkpoint and its interface metadata, then independently measures every physics transition, including actual contact forces, raw and qualified twist, support sources, command rates, and failures. The run0004 15k checkpoint reached a peak force-qualified angle of 2.18460 rad (125.17°), then dropped at 8.7 seconds. This is partial motion, not a successful turn. Evidence is in `artifacts/bootstrap_0004/audit_progress_0001/report.json`.

The MPC rotation tilt cost now compares with the episode's actual initial axis, including noncanonical object orientations. Tests cover an initial axis along palm z and a 0.25 rad relative tilt. A separate 20-candidate longitudinal-grasp search found no acceptable initialization; its static kinematics suggestions remain untested. The 30k policy audit peaked at 106.43° and later dropped, so the 15k peak is not evidence of monotonic learning improvement. The earlier complete test suite passed 83 tests; current verification and process state are recorded in `WORK_STATE.md`.

The companion rotation setup explicitly holds the object without palm support ([III-B1](https://arxiv.org/html/2609.14868v1#S3.SS2.SSS1.p2)). The original local retention gate omitted this condition. Probe0002 genuinely rotated through a full turn but used substantial palm contact force, and is now marked ineligible for the task. The corrected gate sums positive normal object/palm contact forces after every physics transition, using a local numerical tolerance of 1e−6 N. A violation is permanent within the episode: further positive retained progress and success are disallowed, and the next control boundary terminates with the failure penalty. The `drop` flag continues to describe actual table/workspace/contact-loss drops; `failure_reason="palm_support"` distinguishes this additional failure. The tolerance and failure handling are independent implementation choices, not published numerical settings. Reorientation is not changed by this rotation-specific rule. New trajectory exports use v3 validation and record episode peak palm normal force and the violation flag; older v2 records are insufficient.

The optional exact C++ rollout evaluator is documented in [native_rollouts.md](native_rollouts.md). It preserves MuJoCo transitions and constraints, with Python scoring and explicit provenance. It improves local evaluator runtime but has not met a 10 Hz planning deadline. `scripts/probe_mpc.py --backend native` selects it explicitly for diagnostic trials and archives numerical source/configuration with each run.

A matched 40 mm diagnostic now completes three consecutive turns over six simulated seconds and retains the object during a further two-second fixed hold. All 3,000 original physics samples replay bit-for-bit; the independent force-qualified angle reaches 23.121914 rad, with zero palm/table/other support. See `artifacts/mpc_matched40_reference_0001/independent_replay_0001/findings.md`. Its prior has six PCA components extracted from measured MPC-plus-hold motion, and its diagnostic search includes exact hold and warm-start reference candidates; this is not the companion paper's four-component SAC-derived prior. Planning required 240.7 wall seconds for six simulated seconds.

The diagnostic data also exposes a learning constraint: roughly half its normalized scalar commands are exactly at actuator bounds. Clipping by the paper's main BC epsilon .02 invalidates the first turn. A 1e−6 clip preserves one turn but fails during later motion. Earlier one-turn BC fits had near-zero supervised loss yet failed closed-loop physics. The paper's main BC setting remains unchanged; bounded bootstrap experiments and explicit diagnostic planner limits are used to investigate the discrepancy, not to label a failed clone successful.

The subsequent bounded-command probe `artifacts/mpc_matched40_bound098_0001` completed one audited turn at 2.2 s. Its effective normalized command range is ±.9799998998641968, chosen inward from ±.98 for stable float32 normalization; physical actuator limits are unchanged. All controls survive the paper's epsilon .02 clamp bit-for-bit. Exact replay matches recorded physics, and both first-success and full-sequence two-second holds remain grasped without external support. A small prespecified sensitivity diagnostic finds two of three successes at uniform command-noise amplitude 1e−6 and none at 1e−4 or 1e−3; this does not estimate a general success rate. Evidence is in the probe's `sensitivity_0001/` and `artifacts/bc_40mm_bound098_0001/audit_report.json`.

A mean-only BC baseline on its first 22 transitions uses the paper's epsilon .02, learning rate .003, batch 256 and 12,000 updates. All five checkpoint evaluations fail by palm contact. At 12,000 updates, teacher-state action MSE is 1.97e−12 and maximum error 1.35e−5, but the physical rollout still fails at 0.4 s. Correct clipping and small supervised error have therefore not established a usable learned controller. This is a one-demonstration diagnostic, not the main 20-demonstration stage; no critic or SAC updates occurred.

The diagnostic motion is also substantially faster than the published hardware motion. The companion paper's III-B3 reports a median successful-turn speed of 18.78°/s for its full method. The local slew-limited trace reaches its first full-turn boundary in 1.7 s (roughly 212°/s for 360° divided by completion time), with peak object angular speed 49.40 rad/s. These different experiments are not a matched performance comparison. They reinforce that the current scene/controller is an independent simulation and that source geometry, actuator calibration and stable policy behavior remain unresolved; the recorded turns do not reproduce the reported hardware operating regime. [Companion paper, III-B3](https://arxiv.org/html/2609.14868v1#S3.SS2.SSS3)

The consistent-continuation diagnostic (`artifacts/bc_common_continuation_0001`) uses nine actual nominal state/action pairs plus three nearby recovery states with identical correction actions. Fresh BC alone fails at 3k/6k/12k updates. One frozen-feature mean-head residual solve reduces actual singleton action error to 4.77e−7 and produces a policy-only strict full turn at 0.9 s, with force-qualified angle 6.651565 rad and no drop or external support. Continued policy control drops at 1.2 s; the training data contains no post-success continuation labels. This establishes first-turn BC feasibility without establishing sustained behavior, stochastic exploration, or a SAC-trained primitive.

A [primary-source audit](../artifacts/bootstrap_source_audit_0001/report.md) separates the companion simulation prerequisite from the main real-world learner. The companion project specifies five extraction trajectories and writes “5 trajectories, ~1 min” without defining whether that duration is aggregate or per trajectory. The companion requires temporal alignment before PCA but does not publish the alignment algorithm or simulation SAC training recipe. The next extraction dataset should record five trajectories from one frozen successful 40 mm SAC checkpoint, individual durations, and the alignment decision. Main BC/SAC and PPO settings are not evidence for the missing companion-bootstrap recipe. [Companion implementation details](https://primitive-informed-mpc.github.io/), [PCA description](https://arxiv.org/html/2609.14868v1#S2.SS4.p2.1)

The [dedicated frozen policy collector](primitive_collection.md) now enforces this source distinction. It records five actual attempts from a copied 40 mm SAC checkpoint, full measured frames and timestamps, and independent 2 ms force audits. Only five qualifying episodes produce the extraction archive. Extraction and main MPC execution verify its checkpoint, evidence and PCA lineage. Bootstrap mixed-policy histories and ordinary BC evaluations remain diagnostic even when they contain physically successful turns. These checks do not solve the still-missing successful SAC policy.
