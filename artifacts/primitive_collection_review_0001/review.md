# Primitive collection provenance review

The current exporters can mislabel a successful imported BC actor (BC12000, online0) as SAC. This is a provenance bug even when its physical turn is valid. No source or physical task was changed during this review.

1. `train_bootstrap.py:530–549` checks physical success but accepts online0. The run records episodes before updates at `:604–625`; checkpoint export at `:491–500` calls all accumulated traces learned bootstrap SAC. Later positive counters do not repair early BC-only episodes. Stochastic training traces can also span multiple actor versions within one episode, and exports pool multiple checkpoints.
2. `cli.py:422–460` permits compatible BC checkpoints for evaluation, which is useful, but labels every successful trajectory deterministic SAC. `validate_checkpoint` authenticates bytes and environment, not a SAC training claim.
3. `cli.py:202–249` validates geometry, v3 retained/no-palm episode evidence, frame counts and contract. It does not require authentic positive online updates, one common checkpoint, policy-only provenance, five40mm episodes, or force-audit file bindings. The source string alone is copied into primitive provenance.
4. Existing `audit_policy.py` preserves2ms force data and actual commands, but not complete transitions or terminal measured joint frames. Generic evaluate exports joint frames without force data and hardcodes4 Torch threads. Neither command alone provides the required complete collection bundle.

The smallest fail-closed correction is to keep generic physical success/evaluation honest and distinct from primitive eligibility. Mark bootstrap history as diagnostic policy trajectories rather than SAC primitive data; retain zero-update successes as such, never promote them when a later checkpoint gains updates. Evaluation should label its actual training history from authenticated checkpoint counters, and remain available to BC policies. Production primitive extraction should require a dedicated frozen-SAC collection kind with five valid episodes, one copied checkpoint hash, actual positive online updates, matching40mm rotation contract/interface, and verified per-episode transition/physics/audit bindings. A checkpoint count at episode completion is insufficient for mixed-policy training traces. Generic mathematical `PrimitiveBasis.from_trajectories` can remain available for explicitly diagnostic arrays.

Root separately authorized a dedicated collector in new files only. It will freeze one checkpoint and preserve all five actual attempts, exporting an eligible archive only when all five independently qualify. Existing cli/bootstrap fixes remain separate until the live-source freeze ends.

Meaningful future regressions: imported BC12000/online0 may complete a real turn yet never gets a SAC-eligible archive; a zero-update success followed by real updates remains ineligible; changing per-episode checkpoint hashes/counters is rejected; missing/tampered audit or transition hashes reject extraction; failed or partial physical episodes never export an eligible primitive; a frozen compatible positive-update fixture can assemble five records with complete initial/terminal frames and identity alignment, with the fixture explicitly synthetic and not physical evidence. Preserve existing tests that reject bad retained rotation/palm support and preserve all main20-demo/12kBC/50kcritic gates.

Existing commands are listed in existing_commands.sh, for a future independently successful40mm SAC checkpoint. They were not run. `audit_policy --run` first copies one committed generation once; all five episodes then use that copy. Its exit code0 means audit completion, not success: require all five `finger_supported_rotation_success` results, no drop or external support, completed status, and matching hashes. Generic evaluate is useful for diagnostics but its SAC label is currently unsafe and its output must not be treated as sufficient production evidence.

Alignment should start with actual reset-relative sampling times0,0.1,…,duration, retain initial and terminal measured joint positions, and keep each episode distinct. For equal-duration trajectories from identical deterministic resets, explicit identity alignment uses only actual measured samples. Report identical resets/trajectories as repeated executions, not robustness or diversity. If durations differ, do not silently claim the raw concatenation is author alignment: preserve raw streams and record the local alignment decision. Any future interpolation belongs only in a clearly marked derived PCA-feature array, never in measured physics/replay or success evidence. The companion alignment algorithm and whether “~1min” is aggregate/per-trajectory remain unpublished; do not pad, extend, splice, or fabricate trajectories to fit that description.
